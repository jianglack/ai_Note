# 短期对话记忆实施前复审

## 结论

设计可以执行，但必须坚持以下边界，否则不能把任务 8 判定为完成。

## 已澄清项

1. **并发边界**：JVM `ConcurrencyGuard` 不作为数据完整性证明；数据库 head 行锁和唯一约束才是最终边界。
2. **分离含义**：本轮采用同表不同生命周期视图。UI 可见历史包含 trimmed 行，模型查询只读取未 trimmed 的有界尾部。物理分表留给多 thread 产品化，不影响本轮“不会把全量历史进模型”的硬门禁。
3. **压缩可靠性**：不能把 fire-and-forget `@Async` 当闭环；必须有持久任务、幂等范围、租约和重试。
4. **回滚**：保留 `MEMORY_CHAT_HISTORY_WRITE_MODE=legacy_rewrite`，但迁移新增的唯一约束和 head 表不回滚删除。
5. **真实性**：压测使用真实 PostgreSQL 和真实 JPA 事务；摘要故障用可控模型桩做确定性注入，不用随机 sleep 伪造结论。

## 实施警戒线

- 不得在迁移中删除现有聊天历史。
- 空 sequence 回填必须从该用户现有最大值之后续排，不能与历史序号碰撞。
- LLM 调用不得持有数据库行锁或长事务。
- worker 失败不得删除或标记原始消息为不可恢复。
- 日志和压测报告不得输出用户聊天正文或 API 密钥。
- 任何只在 Mockito 中通过、未经过 PostgreSQL 并发验证的结论都不能写成“并发安全”。

## 预期变更风险

- V60 首次启动会回填少量历史空 sequence，需要在迁移回放和真实库启动中验证。
- 唯一约束会暴露已有潜在重复序号；迁移必须先规范化再建约束。
- TokenWindow 与 tool-call 对必须联合测试，避免窗口从孤立 tool result 开始。
- 压缩 worker 引入后台模型成本，默认批次、最小轮数和重试上限必须可配置并可关闭。

## 审核结果

`APPROVED_WITH_GATES`：可以进入测试先行实现；只有所有硬门禁和最终复审通过后，任务 8 才能标记完成。
