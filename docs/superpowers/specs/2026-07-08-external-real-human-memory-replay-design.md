# External Real Human Memory Replay Design

## Goal

Add an auditable external real-human replay source for memory evaluation when product-local real user data is too small. The dataset must come from public, documented human conversation corpora and must be filtered for this product's memory-governance scenarios before entering replay.

This design does not label external public data as product user data. Product-local samples remain `product_real_user_anonymized`; public human conversation samples use `external_real_human_conversation`.

## Source Choices

Primary source:

- WildChat (`allenai/WildChat`)
  - Public Hugging Face dataset.
  - Real human users interacting with ChatGPT.
  - Multilingual, includes ambiguous requests, code-switching, and topic switching.
  - Dataset card lists ODC-BY license and de-identification.

Fallback sources:

- OpenAssistant OASST1 (`OpenAssistant/oasst1`)
  - Human-generated and human-annotated assistant-style conversations.
  - Apache-2.0.
  - Useful as a quality-reviewed supplement.
- LMSYS-Chat-1M (`lmsys/lmsys-chat-1m`)
  - Real-world LLM conversations.
  - License is stricter, so it should be optional and not used as the default committed fixture source.

## Source Type Contract

Allowed replay source types after this phase:

| Source Type | Meaning | Real Human? | Product User? | Allowed In Active Replay? |
| --- | --- | --- | --- | --- |
| `synthetic_seed` | Hand-authored deterministic seed data. | No | No | Yes |
| `simulated_realistic` | Agent/persona-generated coverage data. | No | No | Yes |
| `external_real_human_conversation` | Public, documented human conversation dataset after filtering and redaction. | Yes | No | Yes |
| `product_real_user_anonymized` | This product's user data after anonymization, review, and approval. | Yes | Yes | Yes |

`external_real_human_conversation` can satisfy a real-human coverage gate. It cannot satisfy a product-user pilot gate.

## Project-Relevance Filter

Do not import random public conversations. A candidate row must match at least one memory-system scenario family:

- Stable preference or explicit memory request:
  - `remember`, `keep in mind`, `I prefer`, `I like`, `I want you to`.
- Interaction style:
  - `tone`, `style`, `format`, `formal`, `concise`, `detailed`, `professional`, `always answer`, `from now on`.
- Correction or supersede pressure:
  - `instead`, `rather`, `no longer`, `don't`, `not`, `I asked`, `previous`.
- Project/work context:
  - `project`, `workspace`, `notes`, `meeting`, `requirements`, `release`, `audit`, `review`.
- Reference-only or RAG-like tasks:
  - `summarize this`, `based on this`, `according to`, `source`, `article`, `note`.
- One-off scope:
  - `this time`, `for this reply`, `in this answer`, `only for now`.
- Assistant feedback:
  - `good answer`, `thanks`, `this helped`, `your answer`.
- Forget/delete/control:
  - `forget`, `don't remember`, `delete`, `remove`.
- Sensitive-like memory boundary:
  - `password`, `token`, `api key`, `secret`.

The importer may use query-based harvesting from Dataset Viewer, but the committed replay artifact must keep only sanitized replay cases and manifest metadata, not raw dataset dumps.

## Labeling

Each imported external case records expected replay labels:

- `expectedCaptureAllowed`
- `expectedDecisionType`
- `expectedMemoryType`
- `expectedCorrection`
- `expectedPolicyReason`
- `expectedSignals`

Labels are generated by the current policy during harvesting, then stored as fixed expectations in the committed replay artifact. Future policy changes must update expectations deliberately, not recompute them silently at test runtime.

## Redaction And Hygiene

The importer must reject or redact:

- emails;
- phone-like long numbers;
- non-example domains;
- AWS-looking keys;
- `sk-` style secrets;
- replacement characters;
- raw IP addresses;
- overly long prompts;
- toxic or flagged rows if moderation fields are available.

The committed artifact must contain:

- replay case ID;
- sanitized user message;
- nonblank assistant output placeholder or sanitized assistant response excerpt;
- source reference such as `hf://datasets/allenai/WildChat/default/train#row_idx=...`;
- dataset name and license in source reference or manifest;
- redaction report ID;
- `reviewStatus=approved`;
- reviewer name;
- approval timestamp.

## Active Dataset Integration

The active replay loader should combine:

- existing `synthetic_seed`;
- existing `simulated_realistic`;
- imported `external_real_human_conversation`.

Minimum external real-human target for this phase:

- 2000 approved external real-human replay cases.

The 2000 external cases are in addition to the existing 2000 synthetic/simulated active cases, making the active replay set at least 4000 cases.

## Quality Gates

Automated tests must enforce:

- active replay total cases >= 4000;
- external real-human cases >= 2000;
- external source type is present and approved;
- external cases do not use `simulated_realistic`;
- external cases do not claim `product_real_user_anonymized`;
- all external rows have source references, redaction reports, reviewers, approval timestamps, language tags, and scenario tags;
- project-relevance tags cover at least the main memory scenario families;
- no PII/secret patterns remain;
- duplicate IDs and duplicate user messages are rejected;
- existing replay/advisor evaluations still pass.

## Out Of Scope

- No claim that external public data came from this product.
- No raw Hugging Face dataset dump committed to Git.
- No live network calls in unit tests.
- No use of LMSYS by default unless its stricter license terms are reviewed and accepted.
- No production import endpoint.

## Acceptance Criteria

- A design and implementation plan define source, filtering, redaction, and provenance.
- The repository contains a deterministic external replay artifact or generator output with at least 2000 approved `external_real_human_conversation` cases.
- The active replay loader includes external real-human cases.
- Sample review service recognizes external real-human data separately from product-local real-user data.
- Tests prove the external corpus is project-relevant, sanitized, and source-auditable.
- Full backend tests pass.
